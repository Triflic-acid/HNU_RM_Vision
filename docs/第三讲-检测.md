# 第三讲：装甲板 / 能量机关检测

> 文件：`lessons/lesson03_detection.cpp`（约 740 行）
> 接口：`include/lessons.hpp`
> 模型：`models/best.onnx`（装甲板）、`models/rune.onnx`（能量机关）

---

## 一、这一讲讲什么

用 **YOLO26n-pose + ONNX Runtime** 从一帧图像里同时得到：

```
一个目标 = 检测框 + 类别 + 置信度 + 4 个关键点（装甲板/符叶的四角）
```

第三讲只做**单帧检测**，不做跟踪、不做解算（那是第四、五讲）。

---

## 二、为什么不用 `cv::dnn`

ROS2 Humble 自带的 OpenCV 4.5.4 解析这个模型会失败：

```
解析 DFL 解码部分的 Add 节点时报 "blob_0.size == blob_1.size"
```

换 opset 10/11/12/13、开不开 simplify 都不行，**OpenCV 5.0 才支持**。
ONNX Runtime 没有这个限制，而且更快（实测 640 输入约 19 ms，CPU）。

## 三、接口

```cpp
enum class DetMode { kArmor, kRune };

struct Detection {
  std::array<cv::Point2f, 4> corners;  // 点序随模式不同，见下
  cv::Rect2f box;
  int class_id = -1;        // 装甲板：0~6；符文恒 0
  bool large_armor = false; // 仅装甲板
  double confidence = 0;
  std::optional<cv::Point2f> center;   // 仅符文：R 标圆心
};

// 主入口
std::vector<Detection> lesson03_detection(const cv::Mat& image,
    DetMode mode = DetMode::kArmor);

// 可选：ROI 放大推理（结果已换算回原图）
std::vector<Detection> lesson03_detection_roi(const cv::Mat& image,
    cv::Point2f center, float zoom, DetMode mode = DetMode::kArmor);

// 可选：亚像素精修（两种算法）
void lesson03_refine_subpix(const cv::Mat& image, std::vector<Detection>& dets,
    int win = 5, float max_shift = 6.0F);
void lesson03_refine_quad_lines(const cv::Mat& image, std::vector<Detection>& dets,
    int pts_per_edge = 15, float max_shift = 8.0F);

// 可选：帧间相位相关（亚像素全局位移）
std::optional<cv::Point2f> lesson03_phase_shift(const cv::Mat& prev, const cv::Mat& cur,
    cv::Rect roi, double min_response = 0.05);
```

### ⚠️ 两种模式的角点顺序不同

| 模式 | 点序 |
|---|---|
| `kArmor` | 左上 → **右上** → 右下 → **左下**（顺时针） |
| `kRune` | 左上 → **左下** → 右下 → **右上**（逆时针，与符文数据集一致） |

模型输出统一是「左上、左下、右下、右上」，所以装甲板分支做了 `{0,3,2,1}` 重排。
**不要"统一"这个顺序**——两个数据集就是这么标的。

## 四、处理流程

```
① letterbox        保持比例缩放到 640×640，灰边填充 (114,114,114)
② HWC BGR uint8 → CHW RGB float 0~1         （static 缓冲区复用，避免每帧 malloc）
③ ONNX Runtime 推理  session 按模式复用（armor / rune 各一份）
④ 解码              [1, C, N] → nc = C - 4 - 8
                    逐列取最高类别分；低于 conf 0.25 丢弃
                    关键点按 (x - pad) / scale 还原到原图
⑤ NMS               cv::dnn::NMSBoxes(conf 0.25, iou 0.45)
⑥ 角点重排          armor: {0,3,2,1}；rune: 原序
⑦ 符文额外一步      模板匹配求 R 标圆心（见第五节）
```

## 五、符文模式：R 标圆心怎么来

**不让网络回归**，因为实测它学不动：

| 方案 | 结果 |
|---|---|
| 5 关键点（4 角 + 圆心） | Pose mAP50-95 = **0.597**（圆心误差 194 px） |
| 4 关键点 + 模板匹配圆心 | Pose mAP50-95 = **0.995**（圆心误差 1.5 px） |

原因：圆心距叶片约 260 px（≈3 倍框宽），网络预测会"塌"到叶片附近。

### 模板匹配的三个要点

**① 用 V 通道而不是灰度**

```
灰度 = 0.299R + 0.587G + 0.114B  → 红 logo 亮、蓝 logo 暗，差 2.6 倍
V    = max(R,G,B)                → 红/蓝都饱和，形状一致
```

实测：灰度蓝方命中 7/60；V 通道红蓝各 60/60。

**② 缩放按几何推导，与模板像素尺寸无关**

```
模板缩放 = k × 叶片框宽 / 模板原生边长      k ∈ {0.30 … 0.50}
```

实测 k：真实比赛 ≈ 0.41，仿真 ≈ 0.35。所以 44 px 和 234 px 的模板都能用。

**③ 两道门**

```cpp
// 硬闸门：没有叶片就不碰 R logo（赛场画面里有多个 R logo）
if (mode == kRune && !detections.empty()) { ... }

// 环形门限：圆心只接受距叶片中心 [2.0w, 3.4w] 的候选
if (r < r_lo || r > r_hi) continue;
```

实测圆心距叶片 **2.54w**（2.29~3.19），其他 logo 落在环外被挡掉。

## 六、可选模块（默认关闭）

| 模块 | 作用 | 实测效果 |
|---|---|---|
| `detection_roi` | 裁 ROI 放大到 640 再检测 | 精度 **不变差**（2.87→3.2~3.5 px），**延迟可降**（640→320 约 4×） |
| `refine_subpix` | `cornerSubPix` 精修四角 | 2.87 → **3.87 px（更差）** |
| `refine_quad_lines` | 四边拟合直线求交 | 待你实测 |
| `phase_shift` | 帧间相位相关 | 未接入主循环 |

**为什么亚像素不提升精度**：标注噪声地板约 2.8 px；且角点语义是"灯条端点"，不是 Harris 角。

## 七、模型与类别

### 装甲板（`models/best.onnx`）

```
输入 [1,3,640,640]   输出 [1,26,8400]     nc = 26-4-8 = 14
```

| 索引 | 类别 | class_id | 大小板 |
|---:|---|---:|---|
| 0–4 | B1–B5 | 1–5 | 只有 B1 是大板 225×125，其余 135×125 |
| 5 | BO 前哨站 | 6 | 小板 |
| 6 | BS 哨兵 | 0 | 小板 |
| 7–11 | R1–R5 | 1–5 | 只有 R1 是大板 |
| 12 | RO 前哨站 | 6 | 小板 |
| 13 | RS 哨兵 | 0 | 小板 |

### 能量机关（`models/rune.onnx`）

```
输入 [1,3,640,640]   输出 [1,13,8400]     nc = 13-4-8 = 1
```

单类 `RUNE`，无大小板之分。

## 八、路径与配置

模型/模板默认走相对路径：

```
models/best.onnx     models/rune.onnx     assets/rune_logo*.png
```

启动时按 **环境变量 → 当前工作目录 → 可执行文件目录向上 5 层** 查找，
所以从仓库根目录、`build/`、甚至软链接启动都能找到。

可用环境变量覆盖：

```bash
export ARMOR_MODEL=/path/to/best.onnx
export RUNE_MODEL=/path/to/rune.onnx
export RUNE_TEMPLATE=/path/to/logo.png
```

**多模板**：`assets/rune_logo*.png` 会被 `cv::glob` 全部加载，取最高分。
加一张 `assets/rune_logo_sim.png` 就能提升仿真画面下的匹配分数（0.76 → 0.98）。

## 十二、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 全部检测为空 | 模型没加载 | 看日志 `[det] 模型加载失败`；检查 `models/*.onnx` |
| 符文没有 R 标圆心 | 模板没加载 | 看日志 `[det] 符文模板缺失`；检查 `assets/rune_logo*.png` |
| `nc` 越界直接返回空 | 模型和模式不匹配 | 装甲板 `[1,26,8400]`、符文 `[1,13,8400]` |
| 角点顺序错乱 | 忘了重排 | 装甲板必须 `{0,3,2,1}` |
| 框对但角点偏 | 标注点序问题 | 用 `fix_kpt_order.py` 批量检查 |
