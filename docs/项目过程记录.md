### 关键决策：为什么不用 `cv::dnn`

**【回忆】** 一开始想用 `cv::dnn::readNetFromONNX`，报错：

```
Unsupported operation: Layer "Split" not supported
```

查了算子支持表，确认 OpenCV 4.5.4 的 DNN 不支持这个 pose 模型的某些算子。

**改用 ONNX Runtime**，并在 CMake 里加：

```cmake
target_link_libraries(training_lessons PUBLIC onnxruntime)
```

### 后处理解码

模型输出 `[1, C, 8400]`，`C = 4 + 1 + 1 + 4×3 = 18`？不对。

实际：

```
C = 4 (box) + 14 (类别) + 4×2 (关键点 x,y) = 26
nc = C − 4 − 8 = 14
```

**【记录】** 代码里 `nc = C - 4 - 8`。

> 那次训练的结论（原文）：
> **同一份数据、同样的超参，仅仅修正 14.6% 的关键点点序，
> Pose mAP50 从 0.839 → 0.917（+7.8），Pose mAP50-95 从 0.812 → 0.894（+8.2），Box 指标不变。**

**【记录】** 出现四个文件：

```

order_report/manual_review.csv

```

**这就是发现"点序不一致"的那一晚。**

### 怎么发现的

**【回忆】** 过程大致是：

1. 从 val 集里抽样，把 4 个关键点画在图上
2. 用脚本按"相邻两点组成的四边形是凸的、且面积>0"判方向
3. 输出 `kpt_order_report.csv`：每个样本的 4 点顺序是否一致

结果：**约 14.6% 的样本点序与主流相反**。

### 为什么这会毁掉精度

```
点 1 = 左上，点 2 = 右上，点 3 = 右下，点 4 = 左下   ← 主流（顺时针）
但 14.6% 的样本是：
点 1 = 左上，点 2 = 左下，点 3 = 右下，点 4 = 右上   ← 逆时针
```

网络要同时拟合两种标签，只能学一个"平均"姿态 → OKS 一直上不去。

### 当时的处理

**【回忆】** 先写了一版 `fix_kpt_order.py` 把逆序样本翻转，但**没有立刻重训**
（当时在收尾第三讲的文档）。

这个修复直到 11-08 才真正用上（v3 训练）。

### 实测结果（与预期相反）

| 方案 | 平均角点误差 |
|---|---:|
| 原始 PnP 重投影 | 2.87 px |
| `cornerSubPix` | **3.87 px**（变差） |
| 四边直线拟合求交 | 2.90 px（持平） |

### 为什么变差

**【回忆】** 分析：

```
YOLO 输出的角点本身是"热力图峰值 + 亚像素偏置"
它已经拟合到一个"网络认为最优"的位置
cornerSubPix 会把它往图像梯度最大的角点拉
而装甲板的角是圆角/被灯条遮挡的，梯度极值并不在真实角上
→ 越优化越偏
```

### 结论写进文档

`RM-亚像素角点与ROI加速方案.md`（00:43）、`RM-亚像素角点实现方法.md`（00:51）
两篇都如实写了"实测无效"。

**【教训】** 后来发现更根本的原因：**标注噪声地板 ≈ 2.8 px**，
任何后处理都不可能突破。

# 2026-11-12 ~ 11-14 · 滤波与门限（过程）

## 11-12 拆解抖动

### 第一份日志分析

```
帧数 1306
帧间隔中位 57 ms（17.5 FPS）
dist 中位 2.22 m
reproj 中位 1.07 px
帧间位移 中位 201 mm
```

### 分解抖动方向

写了个脚本把位移拆成径向/切向：

```python
rad = abs(|p_i| - |p_{i-1}|)                       # 沿视线
tan = angle(p_i, p_{i-1}) * |p|                    # 垂直视线
```

结果：

```
径向抖动 中位 80 mm
切向抖动 中位  3 mm      ← 差 26 倍
```

**【判断】** 方向很稳，是**深度**在跳 → PnP 的深度弱约束。

### 但提出过一个错误假设

**【回忆】** 当时说"近处目标四角可能出画或被裁"。用户直接否掉：
"四角可能部分出画或被裁不存在"。

重新算：1.34 m 处小板 135 mm → 投影 88~117 px，**根本出不了画**。
假设作废。

## 11-12 门 1 + 门 2

### 门 1：框宽下限

统计发现跳变帧的框宽中位 **30 px**，正常帧 **81 px**。

```cpp
if (detections[i].box.width < 40.0F) continue;
```

效果：`dist` 最大 20.8 m → 4.7 m。

### 门 2：两路距离互校验

**【回忆】** 那些 16 m 的帧**重投影反而更小**（0.31 px vs 0.95 px）——
因为 30 px 的小四边形在远处也能拟合得很好。所以重投影门限拦不住。

改成比对单目估距：

```cpp
const double d_pnp  = p_cam.norm();
const double d_mono = fx * W / d.box.width;
if (d_pnp > 1.8 * d_mono || d_pnp < 0.55 * d_mono) return degrade();
```

效果：`dist > 5 m` 的帧从 3.8% → **0%**。

## 11-13 马氏门限的失败

### 加了什么

```cpp
const double maha2 = y.transpose() * S.inverse() * y;
if (maha2 > 9.0 && y.norm() > 0.5) return;   // 3σ + 物理门限
```

### 日志立刻变差

```
帧间位移 中位 231 mm（之前 213）
|p|/dist 异常帧 21%
等效速度 90 分位 19.75 m/s，最大 120 m/s
```

### 找原因

打印了 736~745 帧：

```
736  |p|=2.71  dist=2.69
739  |p|=4.13  dist=3.34
740  |p|=4.89  dist=3.81
741  |p|=5.98  dist=3.74   ← 突然 5.98
742  |p|=3.87  dist=3.40
```

`dist` 一直稳，`|p|` 却在涨 → **只有 predict，没有 update** → 量测被门限拒了。

### 为什么会被拒

```
各向异性 R 让横向 3σ 只有 38 mm
目标横移 1 m/s → 每帧 55 mm > 38 mm → 拒绝
拒绝后 KF 外推 → 偏差更大 → 更该拒绝 → 正反馈
```

### 决策

**【回忆】** 删掉整段门限，只保留门 1 + 门 2。

```cpp
// 删除：
// const double maha2 = ...
// if (maha2 > 9.0 && y.norm() > 0.5) return;
```

# 2026-11-14 ~ 11-15 · 旋转目标（详细过程）

## 第一步：确认现象

```
旋转段帧间位移 90 分位 672~845 mm
平移段只有 30~50 mm
spin_rate 中位 8.3（真值 2.0）
```

## 第二步：试滑窗圆周模型

### 做法

```cpp
SpinModel:
  push(t, p);
  中心 = 窗口内坐标中位数
  半径 = 到中心的距离中位数
  相位 = atan2(p - C)          // 每帧重锚定
  ω = 用"相邻帧同板"的样本做最小二乘
```

### 发现中位数估圆心是错的

写了个合成数据脚本：

```python
# 4 块板绕中心转，只看到朝向相机的一段弧
for arc in (90, 120, 180, 360):
    # 用中位数 vs 均值 vs 圆拟合 估圆心
```

结果（半径 0.2 m）：

| 可见弧 | 中位数误差 | 均值误差 |
|---|---:|---:|
| 90° | 188 mm | 182 mm |
| 120° | 181 mm | 168 mm |
| 180° | 153 mm | 131 mm |
| 360° | 77 mm | 43 mm |

**【判断】** 样本集中在弧上，中位数被拉向弧的方向，估的是"弧的中心"。

### 改成 Gauss-Newton 圆拟合

```
min Σ (|p_i − C| − r)²
```

同样的合成数据：

| 可见弧 | GN 圆拟合 |
|---|---:|
| 90° | **7.2 mm** |
| 180° | **4.7 mm** |
| 360° | **2.5 mm** |

好 25 倍。

### 但真机还是差

```
ω 仍被估成 8.3
```

分析：半径用"距离中位数"估，而种子中心本身偏 → **r 被低估**
→ φ 噪声放大 → LS 斜率被拉高。

### 修正：半径用先验，不估

```cpp
radius_ = kPriorRadius;   // 0.20
```

合成验证：弧 90° 时 ω 误差中位 **0.06 rad/s**。

## 第三步：9 维圆周 EKF

### 状态

```cpp
x = [ xc, vxc, yc, vyc, θ, ω, r, z, vz ]
```

### 第一次测试：ω 学不出来

合成数据（真值 ω=2.0）：

| qθ | qω | 估出 ω |
|---|---:|---:|
| 0.30 | 0.60 | **+0.40** |
| 0.01 | 2.00 | **+0.20** |
| 0.001 | 4.00 | +1.26 |

### 想了两天才明白

**【回忆】** 读同济 `target.cpp` 时看到 `update_ypda` —— 量测是
**yaw / pitch / distance / angle**，其中 `angle` 是**装甲板自身的 yaw**。

我们只用位置，`h(x)` 里根本没有 ω：

```
每帧的 update 都能直接改 θ（∂h/∂θ ≠ 0）
→ 滤波器永远"用观测改 θ"，不需要 ω
→ ω 停在 0 附近
```

### 加一维量测

```cpp
y(3) = plate_yaw − θ;      // 角度残差（解缠到 [-π, π]）
H(3, 4) = 1.0;             // θ 直接可观测
```

结果：

| σ_a | 半径 | **ω** | 250 ms 误差 |
|---|---:|---:|---:|
| 0.05 | 0.199 | **2.00** | 54 mm |
| 0.15 | 0.178 | **2.00** | 59 mm |
| 0.40 | 0.159 | **2.01** | 64 mm |

**ω 精确收敛。**

### 但真机更差

```
旋转段 90 分位：672 → 845 mm
```

【判断】硬件上的装甲板 yaw 有 **180° 符号模糊**（板子左右对称），
`atan2` 会让 θ 跳 π。

试了"用 (p − C) 的方向定符号"（朝外）：

```cpp
if (nw.dot(radial) < 0.0) nw = -nw;
```

结果仍 845 mm。

## 第四步：先关掉

```cpp
constexpr bool kEnableSpinEkf{false};
```

旋转段 845 → **267 mm**（最好 87 mm）。

## 第五步：整车观测（多板关联）

### 想法

单板时，换板让位置跳 2r ≈ 0.4 m，被当成运动。
**把当帧所有可见板都喂进去**，车体状态就有多重约束。

### 实现

```cpp
struct PlateObs { Eigen::Vector3d p; double yaw; double sigma_a; };

int update_multi(const std::vector<PlateObs> &plates, int armor_num) {
    for (obs : plates) {
        phi = atan2(obs.p.y - yc, obs.p.x - xc);
        // 与预测的 θ + i·2π/N 比对，取残差最小的 id
        // 残差 > 45° → 丢弃
        update_with_angle(obs.p, obs.yaw, obs.sigma_a, best_id, N);
    }
}
```

### 合成验证

```
每 7 帧换板、1~2 块可见、3 cm 位置噪声、0.15 rad yaw 噪声
```

| 方案 | 半径 | ω | 250 ms 误差 |
|---|---:|---:|---:|
| 单板（无关联） | 0.102 | **+5.64** | 466 mm |
| **整车（多板关联）** | 0.223 | **+1.93** | **88 mm** |

## 第六步：板数

**【回忆】** 用户提出"armor_num 不应当锁死为 4"。

去翻同济 `tracker.cpp`：

```cpp
if (is_balance)   Target(armor, t, 0.2000, 2, P0);   // 平衡步兵 2 块
else if (outpost) Target(armor, t, 0.2765, 3, P0);
else if (base)    Target(armor, t, 0.3205, 3, P0);
else              Target(armor, t, 0.2000, 4, P0);
```

**N 真的不总是 4。**

改成表：

```cpp
int armor_count(int class_id, bool large_armor) {
  if (large_armor && (class_id == 3 || 4 || 5)) return 2;
  if (class_id == 0) return 3;
  return 4;
}
```

又实现了"用同帧两板夹角判 N"，但实测会引入不稳定
（合成：固定 N 时 88 mm，在线判 N 时 258~434 mm）→ **默认关闭**。
